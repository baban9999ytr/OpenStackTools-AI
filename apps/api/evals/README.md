# Phase 8A AI evaluation

Project Astra baseline checkpoint: the existing 68-case runner initially failed four outdated unformatted-price assertions. The listing assertions now verify structured price/currency and localized rendering. The repaired baseline passes 64 applicable backend checks and skips four no-action cases. This is not the requested expanded 75+ scenario suite; see `PROJECT_ASTRA_ARCHITECTURE_AND_IMPLEMENTATION_REPORT.md` for remaining work and verification boundaries.

`npm run eval:deterministic -w apps/api` runs 68 original synthetic scenarios (34 English, 34 Turkish) against a deterministic responder and an ephemeral MongoDB replica set. The first score checks selected tools, strict argument syntax, expected filters and unsupported raw model claims. The second score has 60 tenant-scoped action/retrieval checks, four provider-failure policy checks and four intentionally skipped backend actions for ambiguous requests. It covers pending confirmations, visitor booking authorization, consent refusal, stale and archived listings, handoff and availability. The deterministic responder intentionally emits each scenario's expected call, so its 68/68 model score is a runner sanity check, **not model accuracy**. Negative controls verify that the scorer rejects invalid tools, malformed filters, unsupported prices, false booking claims and tenant marker leakage. No persistent database or real provider is used.

`npm run eval:typecheck -w apps/api` typechecks the evaluation code separately from the production build.

## Opt-in live model-only mode

`npm run eval:live -w apps/api` exits before a network request unless all four opt-ins are `1`: `EVAL_LIVE`, `EVAL_SPEND_APPROVED`, `EVAL_DEDICATED_PROJECT_CONFIRMED`, and `EVAL_PRICES_VERIFIED`. An operator must also supply a dedicated `OPENAI_API_KEY`, `EVAL_MODEL_ID`, `EVAL_MAX_SPEND_USD` (maximum 0.10), and `EVAL_PRICE_FILE`. Copy `prices.example.json` to the ignored `prices.local.json` and enter current provider prices after checking the source. The model must match, the source must be HTTPS, prices must be positive, and the verification date must be within seven days. Never commit the filled file or key. Set secrets through a local ignored environment, not a command line argument.

Optional `EVAL_LIVE_SCENARIOS` selects one to five comma-separated IDs from `scenarios.ts`; `EVAL_REASONING_EFFORT` defaults to `none`, and `EVAL_MAX_COMPLETION_TOKENS` defaults to 128 with a hard cap of 128. Run separately with each configured model ID to compare results; neither model availability nor pricing is assumed. The SDK has no automatic retries. A conservative pre-request estimate must fit under the local cap, and execution stops on the first provider error. Provider timeouts may still incur an unknown charge; reconcile provider billing separately.

Live mode calls the model directly with synthetic prompts, then scores model output. It does not execute backend actions or measure end-to-end task completion. Its completion number is explicitly a **model behavior proxy**. It records tool selection, invalid calls, factuality flags, latency, provider-reported token counts, estimated cost and errors without printing prompts, keys, raw records or provider responses. For safe release decisions, run the full application behind the existing budgets and confirmation controls and inspect any errors manually. The regex factuality checks are conservative indicators, not a semantic truth judge.
